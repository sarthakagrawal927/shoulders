# Dependency visualization directions

Preview-only comparison requested by the owner. No application code changed. Generated with the built-in image tool; exact prompts are in `prompts.json`. These are design mockups, not working interactions or publication-ready research diagrams. Owner selected A, “but much simpler”, then instructed implementation. The simplified tree is implemented; these images remain historical comparison mockups.

Shared purpose: help curious users and builders explain what VS Code stands on, what it adds, and how to use a lower component. Shared screen job: select Node.js within VS Code, read its role and the product contribution, then follow V8 or inspect evidence. Content is held constant across directions.

| Direction | Visual system | Interaction | Signature | Tradeoff |
| --- | --- | --- | --- | --- |
| A: Branching tree | White field-guide page, strong humanist sans, pine active path, ochre branch rules, compact pixel objects | Open branches progressively; selected node attaches to an inline explanation | Software objects form a stepped root system | Clearest relationships, but trees need careful reflow on mobile; scenic ornaments should be reduced |
| B: Small supports, big tools | Cream editorial poster, bold condensed headline, red active frame, a large tool supported by smaller pixel modules | Selecting a support opens the explanation strip beneath the structure | Disproportion between finished application and focused foundations | Memorable metaphor, but size must never imply fragility, contributor count or sole dependency; remove generated slogans and extra signs |
| C: Beneath the surface | Midnight excavation notebook, ivory slab-serif headings, cyan selection, copper stratum divisions | Descend through one chosen branch; unopened siblings stay compact | Visible depth extends from software to physical foundations | Strongest sense of discovery, but dark terrain can compete with text; depth numbers must be ordinal layers rather than literal metres |

Files: `direction-a.png`, `direction-b.png`, `direction-c.png`.

Implementation invariants after selection: real HTML labels and controls, evidence-backed branches, conditional platform scopes, shareable routes, keyboard and reduced-motion support. Pixel art supplies character; it does not establish relationships. Generated explanatory copy and labels must be replaced with checked dataset content. The support metaphor borrows the general idea of disproportionate dependencies; it does not reproduce an existing comic or establish maintainer fragility.
